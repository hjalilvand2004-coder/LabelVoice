## جریان پردازش

```
دوربین / بارگذاری تصویر
      ↓
اعتبارسنجی فایل (نوع واقعی، اندازه، پیکسل) + اصلاح EXIF
      ↓
ارزیابی کیفیت (تاری، نور، انعکاس) + راهنمای عملی فارسی
      ↓
OpenCV: برش دستی، صاف‌کردن چرخش، CLAHE، چند نسخه پردازشی
      ↓
OCR قابل تعویض: Tesseract (fas+eng) یا EasyOCR (fa+en)
      ↓
نرمال‌سازی نویسه‌ای + استخراج فیلدهای ساختاریافته با شواهد
      ↓
کنترل تناقض/ابهام + پاسخ فارسی قالبیِ وفادار به شواهد (+ LLM اختیاری خاموش)
      ↓
TTS فارسی (edge-tts با gTTS جایگزین؛ فقط با رضایت کاربر)
      ↓
رابط Streamlit راست‌به‌چپ: کادر OCR، جدول فیلدها، اصلاح دستی، JSON، صوت
```

## 🧭 تازه در v1.8.0 — بازطراحی موتور فارسی + گرافیک جدید دو سامانه

با بازخورد کاربر روی تصویر واقعی «جعبه لانزول ۳۰» (متن فارسی و خوش‌نویسی برند)، موتور خوانش از پایه بازطراحی شد و رابط کاربری هر دو سامانه مدرن شد:

**موتور خوانش (ریشه‌یابی خروجی آشغال فارسی):**
1. **گذرهای زبانی جدا**: ترکیب `fas+eng` (ریشهٔ تزریق حروف لاتین به کلمات فارسی مثل «کپسول Sy انتریک») حذف شد؛ کاوش مقایسه‌ای سریع تصویر فارسی‌غالب/لاتین‌غالب را تشخیص می‌دهد و فقط زبان برنده اجرا می‌شود (`ocr/tesseract_provider.py`).
2. **واریانت جداسازی جوهر رنگی** (`ink_isolated`): 255−max(B,G,R) — متن آبی/بنفش/قرمز روی جعبه سفید به جوهر تیره روی زمینه روشن تبدیل می‌شود (`preprocess.py` + `js/preprocess.js`).
3. **رأی‌گیری اجماعی**: هر ناحیه توسط چند پیکربندی (واریانت×PSM×موتور) خوانده می‌شود؛ خوانش تک‌منبعِ کم‌اطمینان حذف می‌شود؛ کادرهای منحط و نشان‌گردِ درشتِ تک‌نویسه (خوانش غلط نشان «۲۸») فیلتر می‌شوند.
4. **موتور دوم مکمل (دسکتاپ)**: EasyOCR نواحی ضعیف را پر می‌کند؛ عبارت‌های چندواژه‌ایِ شلِ آن حق ندارند کلمهٔ دقیق تسراکت را له کنند (قوانین جایگزینی چندواژه/تک‌واژه + دو گذر ادغام).
5. **بازسازی سطرها**: تلورانس Y نسبی + شکست ستونی + حذف خوانش هم‌ستون — دیگر واژه‌های تکراری («کپسول کپسول») و سطرهای چسبیده ساخته نمی‌شود.
6. **دروازه‌های نام سخت‌گیرانه‌تر**: نام ساختاری («کپسول انتریک کوتد»)، بریده («پرازول»)، تکرارِ مادهٔ مؤثره، تک‌منبع (امضای دست‌نویس) و تک‌واژهٔ کم‌اطمینان نام نمی‌شوند؛ استخراج مادهٔ مؤثره از سطرِ بعدِ «حاوی:» و اصلاح واژه‌نامه‌ای محدود (کیسول←کپسول، هاوی←حاوی…).

**نتیجه روی جعبه لانزول ۳۰:** ماده مؤثره «لانسوپرازول»، قدرت «۳۰ میلی‌گرم»، تعداد «۲۸ کپسول» و شکل «کپسول» به‌درستی خوانده شد؛ نام خوش‌نویسیِ برند صادقانه «خوانده نشد» اعلام گردید (به‌جای زباله).

**رابط کاربری هر دو سامانه:**
- **دسکتاپ (Streamlit):** سایدبار گرادیانی با ۴ صفحه — 💊 خواندن دارو، 📊 گزارش‌ها و ارزیابی، 📚 راهنما و مستندات فنی، 👥 دربارهٔ طراحان؛ خط‌زمان مراحل رنگی زنده (🔵 OpenCV، 🟣 OCR، 🟠 فیلدها، 🟢 پاسخ، 🩷 TTS) با انیمیشن «در جریان»، هیرو گرادیانی، کارت‌های نتیجه و کاشی‌های ارزیابی.
- **موبایل (PWA):** تب‌بار پایین با همان ۴ بخش؛ مراحل با حاشیه و آیکون رنگی متمایز + انیمیشن نبض هنگام اجرا؛ صفحه گزارش با کاشی‌های ارزیابیِ آخرین اجرا؛ کارت طراحان؛ هدر گرادیانی جدید و کش-باست دارایی‌ها (SW v8).

## 🧭 تازه در v1.7.0 — اصلاح اساسی کیفیت OCR (رفع خروجی بی‌معنی و هشدارهای کاذب)

با بازخورد کاربر روی تصویر واقعی (جعبه کمک‌دستی با متن سفید روی زمینه سبز-آبی)، چهار اصلاح ریشه‌ای اعمال شد که در هر دو نسخه دسکتاپ و موبایل یکسان است:

1. **واریانت جدید «متن روشن روی زمینه تیره»** (`white_on_dark`): آستانه‌گذاری تطبیقی برای نام سفید روی جعبه‌های رنگی — بدون آن «MEDICINE/BOX» اصلاً خوانده نمی‌شد (`preprocess.py` + `js/preprocess.js`).
2. **ادغام «بهترین-اول» نسخه‌ها با امتیازدهی**: به‌جای ریختن همه خوانش‌ها در یک سبد (که سطرهای فرانکشتاین می‌ساخت)، هر نسخه امتیاز می‌گیرد و بهترین مبناست؛ جانشینی فقط با «خوانش کامل‌ترِ معتبر» (احتوای متنی/طولانی‌تر) — خوانش جزئی آشغال با اطمینان بالا دیگر متن سالم را خراب نمی‌کند (`pipeline.py` + `js/pipeline.js`).
3. **گیت کیفیت قطعه‌ها**: نمادهای محض (@ ، » ، °)، اطمینان زیر ۰٫۳ و قطعه کوتاه با کادر غول‌پیکر (شکست تحلیل چیدمان) قبل از ادغام حذف می‌شوند.
4. **دروازه نام معتبر + حذف هشدارهای کاذب**: سطر آشغال (مثل «RIE [SE ۱ ES {= ray WE») دیگر نام نمی‌شود؛ هشدار «تصویر شسته‌شده» فقط با شستگی واقعی (کنتراست کم + میانگین روشن بالا) صادر می‌شود؛ هشدار «چند ناحیه» فقط با نام دومِ تک‌خطی معتبر؛ و پاسخ فارسی ابتدا اطلاعات خوانده‌شده را می‌گوید و بعد هشدار را.

همچنین در خروجی مرحله ۲ (OCR) خط‌زمان v1.6.0، **مقایسه نسخه‌های پردازشی** (تعداد قطعه، اطمینان و امتیاز هر نسخه) شفاف نمایش داده می‌شود تا دقت هر مرحله قابل بررسی باشد.

## 🧭 تازه در v1.6.0 — اعلام مرحله‌به‌مرحله پردازش و ارزیابی مرحله‌ای

در حین پردازش، سامانه مطابق نمودار معماری ملزومات استاد (استاد قربانی) اعلام می‌کند «الان کدام بخش از نیازمندی انجام شد»؛ برای هر مرحله از ۵ مرحله (OpenCV ← OCR ← کنترل فیلدها ← پاسخ فارسی ← TTS+رابط)، **خروجی واقعی** و **معیارهای ارزیابی کیفیت همان مرحله** (تیزی/کنتراست تصویر، اطمینان OCR، پوشش شواهد فیلدها، عبور از نگهبان ایمنی، وضعیت صوت) با دکمه «خروجی و ارزیابی» نمایش داده می‌شود و **گزارش ارزیابی مرحله‌ای (JSON)** قابل دانلود است — در هر دو نسخه دسکتاپ (`label_reader/stages.py` + `stage_callback` در `pipeline.py`) و موبایل (خط‌زمان مراحل در `js/app.js` + `onStage` در `js/pipeline.js`).

## نسخه موبایل و قابل حمل (بدون پایتون!)

نسخه‌ای کامل از این محصول در پوشه **`mobile-app/`** قرار دارد که **بدون پایتون، بدون پای‌چارم، بدون نصب هیچ وابستگی‌ای** روی هر سیستم و هر گوشی اجرا می‌شود — فقط یک مرورگر مدرن لازم است:

- **ویندوز:** دابل‌کلیک روی `mobile-app/شروع-در-ویندوز.bat` (سرور محلی با PowerShell؛ بدون دسترسی مدیریتی) یا مستقیم `index.html` را باز کنید.
- **موبایل (اندروید/iOS):** پوشه را روی یک میزبان HTTPS (مثل GitHub Pages) بگذارید و «افزودن به صفحه اصلی» بزنید — به‌صورت اپ (PWA) نصب و آفلاین اجرا می‌شود؛ از v1.2.0 دکمه «دوربین زنده و خواندن جعبه» دارد (getUserMedia + تشخیص خودکار جعبه) و از v1.3.0 راهنماهای مودالی با معرفی فناوری هر بخش دارد (دکمه «؟»). **اندروید ۷ به بالا؟** APK آماده را از Releases نصب کنید (`LabelVoice-Android-1.8.2.apk`). بخش «📊 ارزیابی و آزمون مدل‌ها» در پایین رابط دسکتاپ و در مستندات (HTML/PDF) نتایج واقعی را با نمودار نشان می‌دهد، و بخش «📌 ملزومات طرح‌شده توسط استاد (استاد قربانی)» با جدول انطباق، پیوند هر الزام به محل پیاده‌سازی‌اش را در هر دو سند و هر دو رابط نشان می‌دهد.
- **تک‌فایل قابل اشتراک:** `mobile-app/label-reader-singlefile.html` — همه چیز در یک فایل HTML.
- کل منطق ایمنی (نگهبان، شواهد، پاسخ قالبی) عیناً از پایتون به جاوااسکریپت منتقل و با ۴۸ آزمون و تست E2E مرورگر راستی‌آزمایی شده است. جزئیات: `mobile-app/README-MOBILE-fa.md`

## راه‌اندازی سریع

```bash
# 1) Python 3.11+ و محیط مجازی
python3 -m venv .venv && source .venv/bin/activate

# 2) وابستگی‌های اصلی
pip install -r requirements.txt

# 3) موتور OCR سیستم
#    Ubuntu/Debian:  sudo apt install tesseract-ocr
#    macOS:          brew install tesseract
#    Windows:        نصب‌کننده UB-Mannheim (راهنمای کامل: docs/INSTALL.md)

# 4) داده زبان فارسی (اگر models/tessdata موجود نیست)
python scripts/download_tessdata.py

# 5) اجرا
streamlit run app.py
```

نصب اختیاری EasyOCR (سنگین — حدود ۲۰۰ مگابایت PyTorch + مدل‌ها):

```bash
pip install -r requirements-easyocr.txt
```

- **پاسخ فارسی قالبی**: فقط از فیلدهای دارای شواهد؛ نمونه:

  > نام درج‌شده روی بسته: Paracetamol. قدرت درج‌شده: ۵۰۰ میلی‌گرم. تعداد درج‌شده: ۲۰ قرص. این اطلاعات از متن قابل خواندن بسته استخراج شده‌اند و توصیه پزشکی یا تعیین مقدار مصرف نیستند.

- **جدول فیلدها** با وضعیت (استخراج‌شده / نامطمئن / غایب / متناقض / اصلاح کاربر)، امتیاز اطمینان و شناسه شواهد OCR.
- **خروجی JSON کامل** شامل قطعات OCR، مختصات، سطرها، فیلدها، هشدارها و فراداده.
- **فایل صوتی mp3** از همان پاسخ تأییدشده (فقط با رضایت صریح برای ارسال به سرویس ابری و دانلود صریح کاربر).

## حریم خصوصی و ایمنی

- پردازش تصویر و متن **کاملاً محلی** است؛ تصویر/متن در لاگ یا فایل ذخیره نمی‌شود.
- ارسال متن به سرویس ابری فقط برای TTS و فقط با چک‌باکس رضایت صریح انجام می‌شود.
- کلیدهای API فقط از متغیر محیط (`LBR_*` یا `.env`) خوانده می‌شوند (نمونه: `.env.example`).
- محتوای OCR «غیرقابل اعتماد» است: هیچ دستور یا کدی از آن اجرا نمی‌شود و آزمون امنیتی دارد (tests/test_security.py).
- سرویس به‌صورت پیش‌فرض فقط روی `127.0.0.1` ارائه می‌شود.
- یادآوری: ممکن است نام بیمار یا اطلاعات شخصی روی بسته در تصویر باشد.

## وضعیت پیاده‌سازی

| بخش | وضعیت |
|---|---|
| بارگذاری/دوربین، اعتبارسنجی، EXIF | ✅ پیاده‌سازی و آزمون شده |
| کیفیت تصویر + راهنمای فارسی | ✅ پیاده‌سازی و آزمون شده |
| پیش‌پردازش OpenCV (برش/چرخش/CLAHE/چندنسخه) | ✅ پیاده‌سازی و آزمون شده |
| OCR: Tesseract fas+eng (dual-PSM) | ✅ اجرای واقعی در این محیط |
| OCR: EasyOCR fa+en | ✅ اجرای واقعی در این محیط (مدل ~۲۸۵MB دانلود شد) |
| استخراج فیلدها با شواهد و تناقض‌ها | ✅ پیاده‌سازی و آزمون شده |
| پاسخ قالبی + نگهبان قواعد | ✅ پیاده‌سازی و آزمون شده |
| LLM اختیاری | ✅ استخوان‌بندی کامل؛ پیش‌فرض خاموش (بدون سرویس واقعی آزمون نشد) |
| TTS: edge-tts / gTTS | ✅ کد و مدیریت شکست؛ تولید صوت به اینترنت وابسته است |
| رابط Streamlit راست‌به‌چپ | ✅ اجرای واقعی (HTTP 200، رندر کامل) |
